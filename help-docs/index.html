Beautiful help window for your server, in 10 lines. Красивое окно справки для твоего сервера — за 10 строк. 用 10 行代码，为你的服务器做出漂亮的帮助窗口。

Server owners write api.* calls in Settings → Help button. The client compiles them locally into a JSON spec; members only ever see the rendered pages — your script never leaves your device and never runs on anyone else's.

Владелец сервера пишет вызовы api.* в «Настройки → Кнопка справки». Клиент локально компилирует их в JSON-спеку; участники видят только готовые страницы — твой скрипт никуда не уходит и ни у кого не выполняется.

服主在「设置 → 帮助按钮」里写 api.* 调用。客户端在本地把它编译成 JSON 规范；成员只能看到渲染好的页面——你的脚本不会离开你的设备，也不会在别人那里执行。

Quick start Быстрый старт 快速开始

One api.* call per line. // comments and blank lines are ignored. Anything else (loops, variables, real JS) is rejected — this keeps the editor CSP-safe and every error points at a line number. api.gate("rules") turns on the rules gate: newcomers see that page on join and cannot write until they accept.

Один вызов api.* на строку. Комментарии // и пустые строки игнорируются. Всё остальное (циклы, переменные, настоящий JS) отклоняется — так редактор остаётся CSP-безопасным, а каждая ошибка указывает на номер строки. api.gate("rules") включает гейт правил: новички видят эту страницу при входе и не могут писать, пока не примут.

每行一个 api.* 调用。// 注释和空行会被忽略。其他写法（循环、变量、真正的 JS）都会被拒绝——这样编辑器保持 CSP 安全，每个报错都会指出行号。api.gate("rules") 开启规则门禁：新成员进入时只看到该页面，接受之前不能发言。

// Rules + FAQ behind the ? button.
api.page("rules", "Rules");
api.text("Server rules", { size: "lg", weight: "bold", align: "center" });
api.text("1. No spam or flooding the chat.");
api.checkbox("read", "I have read the rules");
api.button("Open FAQ", { toPage: "faq" });

api.page("faq", "FAQ");
api.text("How do I get a role? Ask an administrator in the chat.");
api.button("Back to rules", { toPage: "rules" });

Flow: Settings → enable “Help button” → paste script → “Compile & preview” → Save. The server stores the compiled JSON (server.settings.update.helpPage), clients read it from server.snapshot.helpPage. Until help.accept, writing answers ACCEPT_REQUIRED; reading stays open. Путь: Настройки → включить «Кнопку справки» → вставить скрипт → «Собрать и предпросмотреть» → Сохранить. Сервер хранит скомпилированный JSON (server.settings.update.helpPage), клиенты читают его из server.snapshot.helpPage. До help.accept писанина отвечает ACCEPT_REQUIRED; чтение открыто. 流程：设置 → 打开「帮助按钮」→ 粘贴脚本 →「编译并预览」→ 保存。服务器保存编译好的 JSON（server.settings.update.helpPage），客户端从 server.snapshot.helpPage 读取。在 help.accept 之前发言会返回 ACCEPT_REQUIRED；阅读保持开放。

API reference Справочник API API 参考

Call api.page(id, title) first, then add blocks to it. Strings accept "…" or '…' with \n / \t / \\ escapes. Сначала вызови api.page(id, title), затем добавляй в неё блоки. Строки — в "…" или '…', работают \n / \t / \\. 先调用 api.page(id, title)，再往里加 block。字符串可用 "…" 或 '…'，支持 \n / \t / \\ 转义。

api.gate(pageId)

Enables the rules gate on that page (one line, anywhere). The gate page must contain an accept button. Newcomers see it on join and cannot write until help.accept; leaving resets acceptance.

Включает гейт правил на этой странице (одна строка в любом месте). На гейт-странице обязана быть accept-кнопка. Новички видят её при входе и не могут писать до help.accept; выход сбрасывает принятие.

在该页面开启规则门禁（任意位置写一行即可）。门禁页必须包含 accept 按钮。新成员进入时看到它，在 help.accept 之前不能发言；退出即清零接受状态。

api.gate("rules");

api.page(id, title, options?)

Starts a new page (tab). id is [a-z0-9-]{1,40} and must be unique; title is 1–80 chars. { audience: "pending" } shows the page only to not-yet-accepted viewers, "accepted" only to accepted ones (display routing; the snapshot carries everything).

Начинает новую страницу (вкладку). id — [a-z0-9-]{1,40}, уникален; title — 1–80 символов. { audience: "pending" } показывает страницу только непринявшим, "accepted" — только принявшим (маршрутизация показа; snapshot несёт всё).

开始一个新页面（选项卡）。id 为 [a-z0-9-]{1,40} 且必须唯一；title 为 1–80 字符。{ audience: "pending" } 只给未接受者看，"accepted" 只给已接受者看（展示路由；snapshot 携带全部内容）。

api.page("rules", "Rules", { audience: "pending" });

api.text(content, options?)

Plain text paragraph (no HTML). Options: size: xs|sm|md|lg (default sm), weight: normal|medium|bold, align: left|center. Content is 1–2000 chars.

Обычный текстовый абзац (без HTML). Опции: size: xs|sm|md|lg (по умолчанию sm), weight: normal|medium|bold, align: left|center. Текст 1–2000 символов.

纯文本段落（不支持 HTML）。选项：size: xs|sm|md|lg（默认 sm）、weight: normal|medium|bold、align: left|center。内容 1–2000 字符。

api.text("Be kind.", { size: "lg", weight: "bold", align: "center" });

api.divider()

Thin horizontal separator. Takes no arguments.

Тонкий горизонтальный разделитель. Без аргументов.

细水平分隔线。无参数。

api.divider();

api.button(label, options?)

Full-width button. variant: secondary|primary; navigation: { toPage: "faq" } opens another page, otherwise the button closes the dialog; { close: true } is an explicit close. { accept: true } sends help.accept with the page's control states (and closes the gate); it cannot be combined with toPage/close. { requires: ["agree"] } (accept buttons only) disables the button until those same-page controls are confirmed, and the server re-checks them.

Кнопка на всю ширину. variant: secondary|primary; навигация: { toPage: "faq" } открывает другую страницу, иначе кнопка закрывает диалог; { close: true } — явное закрытие. { accept: true } отправляет help.accept с состояниями контролов страницы (и закрывает гейт); несовместим с toPage/close. { requires: ["agree"] } (только accept-кнопки) блокирует кнопку, пока контролы той же страницы не подтверждены; сервер перепроверяет их.

全宽按钮。variant: secondary|primary；导航：{ toPage: "faq" } 打开另一页，否则关闭对话框；{ close: true } 为显式关闭。{ accept: true } 发送带本页控件状态的 help.accept（并关闭门禁）；不可与 toPage/close 同用。{ requires: ["agree"] }（仅 accept 按钮）在同页控件确认前禁用按钮，服务器会再次校验。

api.button("Accept", { variant: "primary", accept: true, requires: ["agree"] });

api.checkbox(id, label, defaultChecked?)

Tick box (e.g. “I read the rules”). State is local-only and never sent to the server. id is unique within the page.

Галочка (например, «Я прочитал правила»). Состояние локальное и никогда не отправляется на сервер. id уникален в пределах страницы.

复选框（例如“我已阅读规则”）。状态仅保存在本地，绝不会发送到服务器。id 在本页内必须唯一。

api.checkbox("read", "I have read the rules");

api.switch(id, label, defaultChecked?)

Toggle switch, same rules as checkbox — local-only state for personal reminders, not server data.

Переключатель, те же правила, что у checkbox — локальное состояние для личных пометок, а не данные сервера.

开关，与 checkbox 规则相同——本地状态，用于个人标记，不是服务器数据。

api.switch("notify", "Notify me about events");

api.select(id, label, options, defaultValue?)

Dropdown with 1–20 unique options (1–80 chars each). defaultValue, if given, must be one of the options. Local-only, like checkbox. Alias: api.combobox(...).

Выпадающий список: 1–20 уникальных опций (каждая 1–80 символов). defaultValue, если задан, обязан совпадать с одной из опций. Локальный, как checkbox. Алиас: api.combobox(...).

下拉框：1–20 个唯一选项（每个 1–80 字符）。defaultValue 若填写，必须是其中之一。和 checkbox 一样只保存在本地。别名：api.combobox(...)。

api.select("topic", "Question topic", ["Roles", "Voice", "Files"], "Roles");

        What admins should know
        Что важно знать админу
        管理员须知
      

      
    
        
  • No real JavaScript runs anywhere: the editor parses calls with a hand-written tokenizer (no eval), viewers render JSON with plain text nodes — no HTML injection surface.
    • 
        
  • Настоящий JavaScript нигде не выполняется: редактор разбирает вызовы рукописным токенизатором (без eval), зрители рендерят JSON обычным текстом — поверхности для HTML-инъекций нет.
    • 
        
  • 任何地方都不会执行真正的 JavaScript：编辑器用手写分词器解析调用（无 eval），浏览端只用纯文本节点渲染 JSON——没有 HTML 注入面。
    • 
        
  • Checkbox / switch / select are personal checklists: their state lives in the viewer's client. The only exception is the help.accept handshake — an accept button sends the current states once so the server can check requires.
    • 
        
  • Checkbox / switch / select — личные чек-листы: их состояние живёт в клиенте зрителя. Единственное исключение — рукопожатие help.accept: accept-кнопка один раз отправляет текущие состояния, чтобы сервер проверил requires.
    • 
        
  • Checkbox / switch / select 只是个人清单：状态保存在浏览者的客户端。唯一的例外是 help.accept 握手——accept 按钮会一次性发送当前状态，以便服务器检查 requires。
