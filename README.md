# OpenCord

OpenCord — открытый децентрализованный клиент для текстового и голосового общения на самостоятельно размещённых серверах.

В репозитории находятся Windows-клиент на Electron и Next.js, общий версированный протокол и локальный Node.js-сервер. Клиент умеет создавать Ed25519-идентичность, подключаться по WebSocket, отправлять сообщения и загружать историю. Сервер различает владельца, администратора и участника, проверяет права на своей стороне и показывает роли в списке участников клиента.

## Запуск

Требуются Node.js 24+ и pnpm 11+.

```bash
pnpm install
pnpm dev
```

Команда одновременно запускает:

- OpenCord Server на `http://127.0.0.1:3210`;
- PGlite-базу в `server/.data/opencord`;
- static export Next.js и Electron Client.

На текущем Windows-окружении Electron запускает локальную static-сборку без HMR: Next.js dev WebSocket несовместим с используемой конфигурацией. После изменения UI перезапустите `pnpm dev`. Сервер продолжает автоматически перезапускаться через `tsx watch`.

Docker и отдельный PostgreSQL для локальной разработки не нужны. В клиенте нажмите «Подключиться», укажите `http://127.0.0.1:3210` и нажмите «Подключиться к серверу». Клиент создаст защищённую локальную Ed25519-идентичность, авторизуется по challenge-response и загрузит серверные каналы и историю. При временном разрыве соединения клиент переподключается автоматически.

Если Docker уже запущен, production-подобный локальный контур с PostgreSQL можно проверить отдельно:

```bash
pnpm docker:up
pnpm docker:logs
pnpm docker:down
```

Он публикует только OpenCord Server на `http://127.0.0.1:3210`; PostgreSQL остаётся во внутренней Docker-сети. `docker:down` не удаляет volume базы.

Для проверки обмена между двумя пользователями можно запустить второй экземпляр клиента с отдельным каталогом пользовательских данных или установить собранное приложение под другой учётной записью Windows. Один каталог данных соответствует одной локальной криптографической идентичности.

## Проверки и сборка

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm package:win
```

Windows-установщик создаётся в `client/release/`.

Проверить сервер без клиента:

```bash
pnpm dev:server
curl http://127.0.0.1:3210/health
```

## Развёртывание сервера на VPS

Production-основа находится в `deploy/`. Кнопка `+` открывает SSH-мастер: он проверяет fingerprint и окружение Ubuntu, после чего предлагает рекомендуемое Docker Compose-развёртывание или явную нативную установку Node.js, PostgreSQL и systemd-службы. Домен можно не указывать для локального теста, например в WSL, но тогда сервер работает по незашифрованному HTTP на порту 3210 и мастер требует отдельно подтвердить риск. Для публичного VPS следует обязательно использовать домен: тогда устанавливается Caddy, включается TLS и проверяется публичный HTTPS healthcheck.

Инструкция, команды `opencordctl`, требования и диагностика: [`docs/deployment.md`](docs/deployment.md).

Модель владельца, ролей и разрешений: [`docs/authorization.md`](docs/authorization.md).
